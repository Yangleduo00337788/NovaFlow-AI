## 1. 架构总览

### 1.1 架构风格

采用**模块化单体（Modular Monolith）**架构作为 MVP 起点，按领域模块划分边界，预留微服务拆分能力。

### 1.2 核心设计原则

| 原则 | 说明 |
|------|------|
| 领域驱动 | 按业务领域划分模块，清晰边界 |
| 插件化 | 模型、工具、解析器均可插件扩展 |
| 多租户原生 | 数据隔离从架构层面保障 |
| 可观测优先 | 全链路 Trace，AI 调用专项监控 |
| 渐进式架构 | MVP 单体 → 按需拆分微服务 |

### 2.4 未来微服务拆分路径

当单体达到瓶颈时，按以下顺序拆分：

```
Phase 1: AI Engine 独立
  novaflow-ai-engine + novaflow-ai-rag + novaflow-ai-workflow-engine
  → novaflow-ai-service（独立 AI 计算服务）

Phase 2: 文档处理独立
  novaflow-knowledge (DocumentProcess)
  → novaflow-doc-service（异步文档处理）

Phase 3: 对话服务独立
  novaflow-chat
  → novaflow-chat-service（高并发对话）

Phase 4: 平台服务
  其余模块 → novaflow-platform-service
```

#### Agent 执行详细步骤

```java
// 伪代码：Agent 执行核心逻辑
public Flux<String> executeAgent(AgentExecuteRequest request) {
    // 1. 加载 Agent 配置
    AgentConfig config = agentConfigService.load(request.getAgentId());

    // 2. 构建 LangChain4j ChatModel
    ChatModel chatModel = llmAdapterFactory.create(config.getModelConfig());

    // 3. 加载对话记忆
    ChatMemory memory = memoryManager.load(request.getConversationId(), config.getMemoryConfig());

    // 4. RAG 检索（如果是 RAG Agent）
    String context = "";
    if (config.getType() == AgentType.RAG) {
        List<RetrievalResult> results = retrievalService.retrieve(
            request.getMessage(), config.getKnowledgeBaseIds(), config.getRetrievalConfig());
        context = buildContext(results);
    }

    // 5. 注册工具
    List<ToolSpecification> tools = toolExecutor.loadTools(config.getToolIds());

    // 6. 构建并执行 Agent
    AiServices.Agent agent = AiServices.builder(Agent.class)
        .chatModel(chatModel)
        .chatMemory(memory)
        .tools(tools)
        .systemMessageProvider(ctx -> config.getSystemPrompt() + context)
        .build();

    // 7. 流式执行并记录 Trace
    return agent.chat(request.getMessage())
        .doOnComplete(() -> traceService.record(config, request));
}
```

## 8. 高可用设计

### 8.1 容错策略

| 组件 | 策略 |
|------|------|
| novaflow-server | 多实例部署，无状态，K8s HPA |
| MySQL | 主从复制，自动故障转移 |
| Redis | Sentinel/Cluster 模式 |
| MinIO | 分布式模式，纠删码 |
| Qdrant | 集群模式，副本 |
| LLM 调用 | 超时重试 + 模型降级 + 熔断 |
| 文档处理 | 任务队列 + 失败重试 + 死信队列 |

### 8.2 LLM 调用容错

```
LLM Request
    │
    ▼
┌──────────────┐    失败    ┌──────────────┐    失败    ┌──────────────┐
│ Primary Model│──────────►│ Retry (x2)   │──────────►│ Fallback Model│
│ (GPT-4o)     │           │ 指数退避      │           │ (GPT-3.5)    │
└──────┬───────┘           └──────────────┘           └──────┬───────┘
       │ 成功                                                  │ 失败
       ▼                                                       ▼
   返回结果                                              返回错误 + 告警
```

### 8.3 缓存策略

| 数据 | 缓存 | TTL | 说明 |
|------|------|-----|------|
| Agent 配置 | Redis | 5min | 配置变更时主动失效 |
| 模型配置 | Redis | 10min | 低频变更 |
| 用户 Session | Redis | 24h | Sa-Token 管理 |
| 对话 Memory | Redis | 会话期间 | 对话结束后持久化 |
| 检索结果 | Redis | 1min | 相同问题短时缓存 |
| 权限信息 | Redis | 5min | 角色变更时失效 |
