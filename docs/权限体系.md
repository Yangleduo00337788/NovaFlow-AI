> 关联：[PRD §2.5 / §4.9.3](./PRD.md) · [v1.1 计划](./v1.1-plan.md) · [数据库设计 §3](./数据库设计.md)

| 章节 | 含义 |
|------|------|
| **一、现状** | 代码和种子数据里实际怎么跑 |
| **二、1.1 目标** | 不改角色模型，把 4 角色做正确 |

## 一、现状（已落地）

### 1.1 模型

```
User
  └── Tenant Membership（一人一租户一个角色）
        └── Role（系统内置 4 个）
              └── Permission（23 个「资源:动作」码）
```

没有多角色表、没有资源级 ACL。Workspace 有实体，但不是授权边界。  
鉴权：Sa-Token + `@SaCheckPermission`。租户：session `tenantId` → `TenantContextFilter` → SQL `tenant_id`。

### 1.2 四个系统角色

| 角色码 | 名称 | 范围 | 演示账号 |
|--------|------|------|----------|
| `super_admin` | 超级管理员 | 全部权限码 + 独有 `platform:manage` | `platform@novaflow.ai` |
| `tenant_admin` | 企业管理员 | 本企业最高；无 `platform:manage` | `admin@novaflow.ai` |
| `developer` | 开发者 | Studio 开发 + 监控只读 + 账单查看 + 门户 | 邀请产生 |
| `user` | 普通用户 | 仅 `/portal` | `user@novaflow.ai` |

组织邀请只能选企管 / 开发者 / 普通用户。层级：超管 > 企管 > 开发者 > 普通用户。  
超管比企管只多跨租户总控；登录后仍带某个租户 session，不是独立平台后台。

### 1.3 权限码（23）

种子：`V11` + `V24` + `V25`；`V26` 从 `user` 收回 `agent:chat`。

| 模块 | 权限码 |
|------|--------|
| Agent | `agent:create` `agent:edit` `agent:delete` `agent:publish` `agent:chat` |
| 工作流 | `workflow:create` `workflow:edit` |
| 知识库 | `knowledge:create` `knowledge:upload` |
| 模型 | `model:config` |
| Prompt | `prompt:create` `prompt:edit` |
| 应用 | `application:manage` |
| 账单 | `billing:view` `billing:manage` |
| 监控 | `monitor:view` `trace:view` |
| 组织 | `tenant:manage` `member:manage` |
| 平台 / 审计 / 搜索 / 门户 | `platform:manage` `audit:view` `search:global` `portal:access` |

工具 / MCP / Skill 没有独立码，接口挂在 `agent:edit`。

### 1.4 角色 × 权限

| | 超管 | 企管 | 开发者 | 普通用户 |
|--|:----:|:----:|:------:|:--------:|
| `platform:manage` | ✅ | ❌ | ❌ | ❌ |
| 组织 / 成员 / 设置 / 审计 / `billing:manage` | ✅ | ✅ | ❌ | ❌ |
| Agent / 工作流 / 知识库 / 模型 / Prompt / 应用 | ✅ | ✅ | ✅ | ❌ |
| `monitor:view` `trace:view` `billing:view` `search:global` | ✅ | ✅ | ✅ | ❌ |
| `portal:access` | ✅ | ✅ | ✅ | ✅ |
| `agent:chat` | ✅ | ✅ | ✅ | ❌ |

开发者**有** `model:config`（不是只读）。普通用户只有门户，不能在 Studio 里「使用 Agent」。

默认首页：超管 `/platform`，企管/开发者 `/dashboard`，普通用户 `/portal`。

### 1.5 前端 / 后端

- 菜单、路由按权限码 OR 过滤；普通用户强制留在门户。
- 按钮级：仅 Agent 页、账单预警较完整；知识库 / 工作流 / 组织对超管成员未锁。
- 后端不检查「该资源是否授权给该用户」，只检查租户 + 权限码 + 业务状态。

## 二、1.1 目标（做正确，不扩角色）

继续用 4 角色和现有权限码。文档、菜单、权限页、接口、种子说同一套话。

必须对齐：

1. 超管唯一多出 `platform:manage`；企管 403 `/api/v1/platform/**`，打不开 `/platform`。
2. 组织内不能分配 `super_admin`；不能改角色 / 禁用 / 移除已有超管成员。
3. 权限页四个角色都展示；默认选中**当前用户自己的角色**。
4. 普通用户只有门户。
5. 开发者看不到组织 / 权限 / 设置 / 审计 / 租户管理。

1.1 明确不做：独立平台账号体系、更细权限码、一人多角色、资源 ACL。

## 三、1.1 代码改动清单（先改这些）

按优先级。**不改角色种子、不加表。**

### P0 — 缺陷（不改会出安全/误读问题）

| # | 问题 | 改哪里 | 怎么改 |
|---|------|--------|--------|
| 1 | 企管可以把超管成员改成开发者、禁用或移出企业 | `OrganizationService.updateMember` / `removeMember` | 当前角色为 `super_admin` 时直接拒绝 |
| 2 | 组织页仍显示编辑/移除 | `novaflow-web/src/views/org/index.vue` | `roleCode === 'super_admin'` 隐藏操作 |
| 3 | 权限页默认选中列表第一项（超管），企管会误以为自己有平台权 | `views/permission/index.vue`；可选 `RoleManagementService.listRoles` 排序 | 默认选中 `auth.roleCode`；展示顺序：企管 → 开发者 → 用户 → 超管 |
| 4 | Redis 里 `tenantId` 可能是 Integer，`(Long)` 强转失败 → 权限列表空 | `StpInterfaceImpl`、`AuthService.currentUser` | 与 Filter 一样按 `Number` 解析；可抽 `SessionTenantIds` |

### P1 — 对齐（体验与注解一致）

| # | 问题 | 改哪里 | 怎么改 |
|---|------|--------|--------|
| 5 | `RoleController` 只认 `member:manage`，Service 允许 `tenant:manage` OR | `RoleController` | `@SaCheckPermission(value={...}, mode=OR)` |
| 6 | Studio 写操作按钮未按权限码隐藏 | 知识库、工作流、Prompt、应用、工具页 | 已按对应权限码隐藏创建/编辑/删除/发布；工作流编辑器只读时不可改画布 |
| 7 | Filter 只处理 Long/Integer | `TenantContextFilter` | 已与 #4 共用 `SessionTenantIds` |

### 不改（刻意）

| 项 | 原因 |
|----|------|
| 把超管从 demo 租户拆走 | 1.1 仍允许超管挂在某租户；用 #1 #2 锁操作即可 |
| `agent:read`、`tool:*`、自定义角色 | Phase 2 |
| 部门表、资源 ACL | 部门表已在 M3 落地；资源 ACL 仍见本文第四节 |

### 改完怎么验

| 账号 | 应看到 | 应被拒 |
|------|--------|--------|
| `platform@novaflow.ai` | Studio + 审计 + 租户管理 | 组织里自己不能被企管改掉 |
| `admin@novaflow.ai` | Studio + 审计；矩阵无「平台超管」勾 | `/platform`、改超管成员 |
| 开发者 | Studio + 监控 + 账单查看 + 门户 | 组织 / 权限 / 设置 / 审计 / 总控 |
| `user@novaflow.ai` | 仅门户 | Studio、总控 |

## 四、以后不做（Phase 2+）

```
Platform Admin     ← 今天 super_admin，应独立权限域（未做）
Tenant Owner / Operator / Viewer   ← 今天没有
Resource ACL       ← 张三只能改某个 Agent（未做）
```

更细权限码（`agent:read`、`workflow:execute`、`tool:*`）和 6 角色矩阵见历史讨论，**不要当成 1.1 需求**。  
也不要用 Spring Security 替换 Sa-Token。

Phase 2 矩阵若让 Member 进 Dashboard，与现状「Member 只能门户」冲突，要单独拍板。
