## 1. 产品概述

### 1.1 产品名称

**NovaFlow AI**

### 1.2 产品定位

NovaFlow AI 是下一代**企业级 AI Agent 开发与运行平台**，帮助企业和开发者通过可视化方式快速创建、编排、部署和管理智能 AI Agent。

### 1.3 Slogan

- 英文：Build Intelligent Agents Faster
- 中文：让企业快速构建下一代 AI 应用

### 1.4 竞品对标

| 维度 | Dify | Coze | FastGPT | LangFlow | **NovaFlow AI** |
|------|------|------|---------|----------|-----------------|
| 定位 | 开源 LLM 应用平台 | 字节跳动 Agent 平台 | 知识库问答 | 可视化 LLM 编排 | **企业级商业化平台** |
| 技术栈 | Python | 闭源 | Node.js | Python | **Java 21 + Spring Boot 3** |
| 多租户 | 有限 | 平台级 | 有限 | 无 | **原生 SaaS 多租户** |
| 工作流 | 有 | 有 | 有限 | 强 | **LiteFlow + Vue Flow** |
| 可观测 | 基础 | 有限 | 基础 | 无 | **OpenTelemetry + Langfuse** |
| 部署 | 自托管为主 | 云端 | 自托管 | 自托管 | **私有化 + SaaS 双模式** |

### 1.5 核心价值主张

1. **降低 AI 应用开发门槛**：可视化 Agent 编排，无需深厚 AI 工程经验
2. **企业级安全与合规**：多租户隔离、RBAC 权限、审计日志、私有化部署
3. **全链路可观测**：从 Prompt 到 Token 消耗的完整追踪与成本分析
4. **Java 生态原生**：面向 Java 企业技术栈，易于集成现有系统
5. **开放工具生态**：MCP、HTTP API、自定义函数统一接入

### 1.6 产品愿景

成为 2026 年 **Java + AI 应用开发**方向的旗舰级项目，打造下一代企业级 AI Agent Operating System。

### 1.7 产品形态（单应用 · 角色分区）

NovaFlow 提供 **一套 Web 控制台、一套登录**。登录后按账号角色进入对应功能区（总控 / Studio / 应用门户），权限由 RBAC 强制，前端菜单按权限裁剪。

| 功能区 | 路由 | 主要角色 | 核心职责 |
|--------|------|----------|----------|
| **总控** | `/platform`、`/audit` | `super_admin` | 管理租户、全局配额与用量、平台级审计 |
| **Studio（工作台）** | `/dashboard` 及开发/治理菜单 | `tenant_admin`、`developer` | 创建 Agent / 工作流 / 知识库，发布应用；组织、权限、账单与监控 |
| **应用门户** | `/portal`、`/portal/apps/:id` | `user` | 使用已发布应用对话；管理员与开发者可进入门户预览 |

Embed（`/embed/agents/{id}`）与 Open API 仍作为无控制台登录的外部接入方式。

**版本与交付边界：**

| 功能区 | v1.0 | 后续规划 |
|--------|------|----------|
| Studio | ✅ 已交付（`novaflow-web` 主体） | 持续增强 |
| 应用门户 | 🔄 v1.1：应用中心 + 对话 | 会话历史等 |
| 总控 | ✅ `/platform`、`/audit` 同站 | 能力增强，不单独拆前端 |

## 3. 使用场景

### 3.1 场景一：企业智能客服

**背景**：某电商企业希望用 AI 替代部分人工客服，处理订单查询、退换货政策咨询。

**用户**：企业管理员 + 开发者 + 客服专员

**流程**：
1. 管理员创建租户，导入产品手册和 FAQ 文档到知识库
2. 开发者创建 RAG Agent，关联知识库，配置 System Prompt
3. 开发者添加订单查询 HTTP Tool，对接 ERP 系统
4. 发布 Agent 到客服工作台
5. 客服专员通过对话界面处理用户咨询，AI 自动检索知识库并调用订单 API

**价值**：客服响应时间降低 60%，人工介入率降低 40%

### 3.2 场景二：内部知识问答

**背景**：某制造企业拥有大量技术文档、SOP、设备手册，员工查找信息效率低。

**用户**：企业管理员 + 开发者 + 全体员工

**流程**：
1. 管理员上传 PDF/Word 文档到 Knowledge Hub
2. 系统自动解析、分块、向量化
3. 开发者创建 RAG Agent，配置检索策略和 Rerank
4. 开发者通过检索测试调优 Chunk 大小和 Top-K 参数
5. 发布到企业内网，员工通过对话查询技术资料

**价值**：信息检索效率提升 5 倍，减少重复性技术咨询

### 3.3 场景三：自动化业务流程

**背景**：某金融企业需要自动化审批流程，结合 AI 判断和规则引擎。

**用户**：开发者 + 业务审批员

**流程**：
1. 开发者在 Workflow Studio 拖拽编排审批流程
2. 配置 LLM 节点进行风险评估
3. 配置条件节点根据风险等级分流
4. 配置 HTTP 节点调用核心系统 API
5. 发布 Workflow Agent，审批员通过界面触发执行

**价值**：审批周期从 3 天缩短到 2 小时

### 3.4 场景四：多 Agent 协作

**背景**：某咨询公司需要 AI 团队完成市场调研报告。

**用户**：开发者

**流程**：
1. 创建 Research Agent（搜索工具 + 网页抓取）
2. 创建 Analysis Agent（数据分析 + 图表生成）
3. 创建 Writer Agent（报告撰写）
4. 通过 Workflow 编排 Multi-Agent 协作流程
5. 用户输入调研主题，系统自动完成调研→分析→撰写

**价值**：报告产出时间从 1 周缩短到 1 天

### 3.5 场景五：API 化 AI 能力输出

**背景**：某 SaaS 企业希望将 AI 能力通过 API 提供给下游客户。

**用户**：开发者 + 外部调用方

**流程**：
1. 开发者创建并调试 Agent
2. 发布为 API 端点，生成 API Key
3. 外部系统通过 REST API 调用 Agent
4. 通过 Model Center 查看调用统计和 Token 消耗
5. 通过 Observability 追踪每次调用的完整链路

**价值**：AI 能力产品化，按调用量计费

### 3.6 场景六：Prompt 模板复用与调优

**背景**：某企业多个 Agent 共用相似的 System Prompt 片段，且需要持续迭代优化。

**用户**：开发者 + 企业管理员

**流程**：
1. 开发者在 Prompt 管理中创建「客服话术」「安全合规」等模板
2. 模板支持变量（如 `{{company_name}}`）和版本管理
3. 创建 Agent 时从模板库引用 Prompt，而非每次手写
4. 通过 A/B 测试对比不同 Prompt 版本的回答质量
5. 将最优版本发布为正式版，关联 Agent 自动同步

**价值**：Prompt 复用率提升 70%，迭代效率提升 3 倍

### 3.7 场景七：费用管控与配额预警

**背景**：某企业 AI 调用量快速增长，需要实时掌握费用并防止超支。

**用户**：企业管理员

**流程**：
1. 管理员在「账单与用量」查看本月 Token 消耗和费用趋势
2. 按模型（DeepSeek/Qwen/GPT）查看用量分布
3. 设置月度 Token 配额和费用预警阈值（如 80%）
4. 超额时系统自动告警并可选限流
5. 导出账单明细用于内部成本分摊

**价值**：AI 成本可预测、可管控，避免预算超支

## 4. 功能设计

### 4.1 AI Agent Studio

#### 4.1.1 Agent 创建

| 配置项 | 类型 | 说明 |
|--------|------|------|
| 名称 | 文本 | Agent 显示名称，租户内唯一 |
| 描述 | 文本 | Agent 功能说明 |
| 图标 | 图片 | 自定义 Agent 图标 |
| System Prompt | 富文本 | 系统提示词，支持变量 `{{input}}` |
| 模型 | 下拉选择 | 从 Model Center 选择已配置模型 |
| Temperature | 滑块 0-2 | 控制输出随机性，默认 0.7 |
| Max Tokens | 数字 | 最大输出 Token 数 |
| Memory | 开关+配置 | 对话记忆类型：无/窗口/摘要 |
| Memory Window | 数字 | 记忆窗口大小（轮次） |
| Tools | 多选 | 从 Tool Marketplace 选择工具 |
| Knowledge Base | 多选 | 关联知识库 |
| Workflow | 选择 | 关联工作流（Workflow Agent） |
| 欢迎语 | 文本 | 对话开始时的欢迎消息 |
| 建议问题 | 列表 | 预设的引导问题 |

#### 4.1.2 Agent 类型

**Chat Agent**
- 普通 AI 对话助手
- 支持多轮对话、Memory
- 适用：通用问答、写作辅助、翻译

**RAG Agent**
- 基于企业知识库问答
- 自动检索 → Rerank → 生成回答
- 支持引用来源展示
- 适用：文档问答、FAQ、技术支持

**Tool Agent**
- 可调用外部工具能力
- 支持：HTTP API、MCP Server、Database、自定义 Function
- LLM 自主决策工具调用
- 适用：订单查询、数据操作、第三方集成

**Workflow Agent**
- 基于预定义工作流执行复杂任务
- 支持条件分支、并行执行
- 适用：审批流程、多步骤任务、Multi-Agent 协作

#### 4.1.3 Agent 调试与发布

| 功能 | 说明 |
|------|------|
| 在线调试 | 右侧对话面板实时测试 Agent 效果 |
| Prompt 版本 | 保存 Prompt 历史版本，支持回滚 |
| 变量测试 | 测试不同输入变量组合 |
| 发布 | 生成 Open API / Embed 嵌入链接（v1.0）；独立 Portal 应用中心（v1.2 规划） |
| 版本管理 | Draft → Published，支持灰度发布 |

#### 4.1.4 Agent 对话

| 功能 | 说明 |
|------|------|
| 流式输出 | SSE 实时返回 LLM 生成内容 |
| 引用来源 | RAG Agent 展示知识库引用片段 |
| 工具调用展示 | 显示 Agent 调用了哪些工具及结果 |
| 对话历史 | 保存对话记录，支持导出 |
| 反馈 | 点赞/点踩，用于优化 |
| 重新生成 | 对不满意回答重新生成 |

### 4.3 Knowledge Hub

#### 4.3.1 知识库管理

| 功能 | 说明 |
|------|------|
| 创建知识库 | 名称、描述、Embedding 模型、分块策略 |
| 文档上传 | 支持 PDF/Word/Excel/PPT/TXT/Markdown |
| 网页导入 | 输入 URL 自动抓取 |
| 数据库同步 | 配置数据源定期同步 |
| 文档列表 | 查看文档状态、大小、分块数 |
| 文档删除 | 删除文档及关联向量 |

#### 4.3.2 文档处理

```
上传 → MinIO 存储 → 格式解析 → OCR（如需）→ 文本提取 → 分块 → Embedding → 写入 Qdrant
```

| 处理阶段 | 技术方案 | 说明 |
|----------|----------|------|
| 格式解析 | Docling / Apache Tika / PDFBox | 按文件类型选择解析器 |
| OCR | PaddleOCR | 扫描件/图片文字识别 |
| 分块策略 | 可配置 | 按字符数/段落/语义分块 |
| Chunk 重叠 | 可配置 | 默认 50-200 字符重叠 |
| Embedding | 多模型支持 | DeepSeek/Qwen/OpenAI/BGE |
| 向量存储 | Qdrant | 按知识库隔离 Collection |

#### 4.3.3 检索配置

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| Top-K | 检索返回数量 | 5 |
| Score Threshold | 相似度阈值 | 0.5 |
| Rerank | 是否启用重排序 | 开启 |
| Rerank Model | 重排序模型 | Jina Reranker v3 |
| Hybrid Search | 向量+关键词混合检索 | 关闭 |

#### 4.3.4 检索测试

- 输入测试问题，查看检索结果
- 展示匹配 Chunk、相似度分数、来源文档
- 支持调优参数后重新测试

#### 4.3.5 权限控制

- 知识库级别：公开 / 团队 / 私有
- 文档级别：按角色授权访问
- 操作权限：查看 / 编辑 / 管理

| 功能 | 说明 |

| 功能 | 说明 |
|------|------|
| Trace 列表 | 按 Trace ID / Agent / 时间 / 状态筛选 |
| 瀑布图 | Span 时间线：LLM 调用、Tool 调用、检索、工作流节点 |
| Span 详情 | 每个 Span 的输入/输出、耗时、Token |
| Prompt 关联 | 显示使用的 Prompt 版本和内容快照 |

#### 4.8.4 可观测中心

综合监控仪表盘，面向管理员和运维人员。

| 指标 | 说明 |
|------|------|
| Agent 调用链 | 完整 Trace 聚合分析 |
| Prompt 版本效果 | 按 Prompt 版本对比成功率、评分 |
| Token 消耗 | 输入/输出 Token 明细，按模型/Agent/用户维度 |
| 响应时间 | P50/P95/P99 延迟分布 |
| 错误率 | 按 Agent/模型/工具统计错误 |

**技术方案**：
- **OpenTelemetry**：分布式链路追踪
- **Langfuse**：LLM 专用可观测（Prompt、Completion、Score）

**告警配置**：

| 告警类型 | 触发条件 | 通知方式 |
|----------|----------|----------|

| 错误率 | 5 分钟内错误率 > 5% | 邮件 / Webhook |
